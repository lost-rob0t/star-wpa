# star-wpa

Wireless actors for StarIntel **0.10.1**, consuming the immutable release generated by **StarLang**. `.star` declarations compile through the maintained StarLang compiler and run on its Common Lisp native actor runtime. Python implements external protocol/tool adapters and numerical solving, not a second actor supervisor.

| Actor | Capability |
|---|---|
| `wpa-kismet` | Kismet dotted-field device JSON ingestion and bounded HTTP collection |
| `wpa-listener` | airodump-ng CSV ingestion, scoped passive capture, receiver observations |
| `wpa-aircrack` | Target-scoped, bounded aircrack-ng invocation; completion receipts exclude keys |
| `wpa-deauth` | Target-scoped, bounded aireplay-ng deauthentication |
| `wpa-gpsd` | GPSD WATCH/TPV ingestion and bounded TCP collection |
| `wpa-trilateration` | Independent receiver multilateration, explicit calibrated RSSI conversion |
| `wpa-wardrive` | WarStar/WiGLE Wi-Fi and Bluetooth observation exports, extracted from server PR #311 |

The Parrot extension adds **57 package tool actors**, covering all 31 packages in the pinned Parrot wireless metapackage plus supplemental Wi-Fi/Bluetooth/NFC/SDR tools, including Wifiphisher and EAPHammer. See [coverage and invocation contracts](docs/PARROT-TOOLS.md).

## Install and validate

Nix is the reproducible build path:

```sh
nix develop
nix flake check -L
nix run . -- listener --request tests/fixtures/listener.json
nix run .#native -- listener "$PWD/tests/fixtures/listener.json"
```

The following direct host setup is also supported:

Requires Python 3.11+, SBCL, Bordeaux Threads and Node.js for view tests. On Debian/Ubuntu install `sbcl cl-bordeaux-threads`. Radio tools and GPSD/Kismet are required only for their live effects.

```sh
python3 -m pip install -e .
python3 scripts/prepare-starlang.py
export STARLANG_SOURCE="$PWD/.cache/star-lang"
export CL_SOURCE_REGISTRY="$PWD//:$STARLANG_SOURCE//:/usr/share/common-lisp/source//:"
python3 scripts/sync-starintel-schema.py --source "$STARLANG_SOURCE"
python3 -m unittest discover -s tests -p 'test_*.py' -v
node tests/views.js
sbcl --script scripts/native-proof.lisp
```

The runtime verifies exact source hashes for either a pinned Git checkout or an immutable Nix source export; dirty Git checkouts are rejected. Schema and runtime share the exact commit in `schema/starintel-schema.lock.json`; the vendored release is copied and checked by the upstream consumer sync tool. Never edit generated contracts locally.

## Use the actors

```lisp
(require :asdf)
(asdf:load-system "star-wpa")
(let ((runtime (star-wpa:start-wireless-runtime)))
  (unwind-protect
       (write-string
        (star-wpa:dispatch runtime "listener" "/absolute/path/request.json"))
    (starlangruntime:shutdown-runtime runtime)))
```

Local native messages are operator-local request filenames. The declarations intentionally have empty portable `accepts`/`produces` contracts: this host adapter boundary is not a new StarIntel document/message type. Emitted JSON batches are validated against generated canonical contracts. No prototype systems are used.

The effect adapter can also be exercised directly:

```sh
star-wpa listener --request tests/fixtures/listener.json > /tmp/wireless-documents.json
```

Each request includes a nonempty `dataset`. JSON inputs/outputs are limited to 8 MiB, and Kismet, listener and GPSD batches to 1,000 records. Provider inputs:

- **Listener**: `receiverId` plus `observations` (BSSID, Unix `observedAt`, optional integer `signalDbm`, numeric receiver `latitude`/`longitude`, optional `distanceMeters`/`rangeAccuracyMeters`); alternatively `csv` from airodump. CSV time defaults to UTC; set `timezoneOffset` to the source offset. `receiverFix` is attached only within `maxFixAgeSeconds` (default five).
- **Kismet**: `receiverId` and `devices` containing actual dotted-field device exports. `operation: "collect"` uses an explicit `url` that returns a device array, with an optional bearer token from `STAR_WPA_KISMET_TOKEN`. Credentialed collection requires the exact URL in deployment-local `kismetTokenUrls`; requests cannot select other environment variables.
- **GPSD**: `receiverId` and `reports` containing TPV objects. `operation: "collect"` supports `host`, `port` and `maxReports`; only mode >= 2 fixes are emitted. Missing source time requires explicit Unix `observedAt`.
- **Wardrive**: `receiverId` or `device_id`, and 1–100 exported `observations` using `id`, `address`, `level`, `latitude`, `longitude`, millisecond `time` and `radio` (`WIFI`, `BLE` or `BT`). HTTP authentication remains the server's responsibility; this package does not expose an unauthenticated ingestion endpoint.

Examples for every adapter are in `tests/fixtures/`. Effect adapters do not publish automatically: they return a validated canonical batch for the maintained ingest boundary or the explicit CouchDB port.

## Active effects and capture

`STAR_WPA_POLICY_FILE` points to deployment-local JSON, never policy supplied by incoming requests:

```json
{"interfaces":["wlan0mon"],"bssids":["aa:bb:cc:dd:ee:ff"],"allowListening":true,"allowAircrack":false,"allowDeauth":false}
```

Capture requests use `operation: "collect"`, `interface`, `durationSeconds` (1–300), optional scoped BSSID and channel. No automatic monitor-mode changes are made. airodump process groups are stopped and reaped after the capture interval.

Aircrack requires `allowAircrack`, a scoped `bssid`, local `capture` and `wordlist` paths. Deauth requires `allowDeauth`, scoped `bssid` and `interface`, a count in 1–100, and optional station MAC. Both need a nonempty `requestId`, `STAR_WPA_EFFECT_DB` pointing to an operator-local SQLite ledger, and a bounded `timeoutSeconds` (1–300). A completed request replay returns its receipt; changing the payload under the same ID is rejected. Crashes/timeouts retain an uncertain attempt and require operator reconciliation before any repeat. Policy is rechecked even on receipt replay. Receipts report process completion, not successful cracking; tool output and recovered keys are never published.

## Canonical evidence and geography

Output is lowerCamelCase with canonical `id`, `dtype`, `dataset`, `schemaVersion`. Geo decimals are canonical decimal **strings**. Source observations become `event` records; adapter details live under `extensions["org.starintel/wpa@1"]`. Transmitters use `wireless-network`, clients use `wireless-station`, Bluetooth uses `network-device`; geometry uses `geo-point` plus `location`. `relation` records link observations, subjects and geometry with explicit evidence.

Receiver GPS fixes are observation geography. They are not copied into AP locations and do not establish ownership or identity. A derived position is a separate geo/location record linked with `estimated-location`, carrying the reading IDs, receiver IDs, temporal window, solver method, calibration and residual RMS. Its reported uncertainty is a conservative local model estimate, not a certified RF confidence interval.

## CouchDB and multilateration

`views/wireless.json` is generated from `views/maps/*.js` and `views/helpers.js`:

```sh
python3 scripts/build-views.py
python3 scripts/build-views.py --check
```

The `_design/wireless` views include transmitter/time, network/time, network/receiver/time, receiver/time, ten-second trilateration windows, reading counts, networks, stations, geo buckets and relation endpoints. Every key includes the dataset. Counts are reading counts, not independent receiver counts. Geo buckets are a rebuildable query projection; they are not an authorization-aware spatial query engine.

Configure `STAR_WPA_COUCHDB_URL` as a database URL, and credentials in `STAR_WPA_COUCHDB_USER`/`STAR_WPA_COUCHDB_PASSWORD`. Do not embed credentials in the URL. The database must already exist.

```sh
python3 scripts/couchdb.py install-views
python3 scripts/couchdb.py publish --file /tmp/wireless-documents.json
python3 scripts/couchdb.py trilateration-input --dataset lab --network-id NETWORK_ID --start 100 --end 110 > /tmp/solve.json
star-wpa trilateration --request /tmp/solve.json > /tmp/estimated-documents.json
python3 scripts/couchdb.py publish --file /tmp/estimated-documents.json
```

The explicit direct CouchDB port is for an operator-controlled database; it does not provide tenant authentication or call retired server routes. It retains canonical `id` and adds CouchDB `_id`/`_rev` only at persistence. Writes validate the batch first, are revision-aware, detect conflicting immutable evidence and support duplicate-safe replay. A batch is not transactionally atomic; replay completes partially written batches.

The resolver groups by dataset, transmitter and fixed Unix time buckets (`windowSeconds`, default 10). It uses the newest reading per receiver, needs at least three independent positioned receivers, rejects degenerate geometry and large residuals, and bounds the local-plane baseline to 5 km by default (maximum 20 km). Boundary-adjacent readings belong to different buckets; this solver does not perform tracking or motion compensation. Polar latitudes above 85 degrees are rejected; longitude wrap is handled. Measured ranges are preferred. RSSI-derived ranges require explicit `rssiModel: {"referenceDbm": -40, "pathLossExponent": 2}`; no assumed calibration is silently applied.

`python3 scripts/live-couchdb-proof.py` provisions its own disposable Docker CouchDB, exercises real view indexing, idempotent replay, graph hydration and four-receiver solving, then removes the container. It requires Docker socket access. Physical RF, a real Kismet deployment and a GPS device remain separate integration checks.

See [migration ownership](docs/MIGRATION.md) and the [implementation evidence](roam/design/wireless/wireless-package.org).

HTTP collection and CouchDB requests reject redirects to prevent forwarding credentials. Configure the final endpoint URL directly. Existing credentialed Kismet deployments must add `"kismetTokenUrls": ["https://kismet.example/devices.json"]` to their local policy.

The effect ledger must be a regular file owned by the running user, with mode `0600` and one hard link; symlinks are rejected. Keep its parent directory private and trusted. Existing ledgers with shared permissions must be corrected locally before execution. Input JSON, manifests and stdin are read as bounded regular files; FIFO/device inputs are rejected. Aircrack/deauth now have the same 1 MiB per-stream limit and process-group cleanup as generic tool actors. These controls do not sandbox installed tools: executable dependencies, PATH, working directories and policy remain operator-trusted.
